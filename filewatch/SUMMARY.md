# Filewatch Summary

## 1) What the tool does
Filewatch monitors file activity at the VFS layer and reports opens, writes, deletes, and renames for regular files. It is lightweight and prints one-line events with PID/UID and inode details.

## 2) High-level architecture
- Kernel space (eBPF): kprobes on VFS helpers emit events to a ring buffer.
- User space: libbpf loader reads ring buffer events and prints a compact line.

Data flow:
1. A file operation occurs in the kernel VFS layer.
2. eBPF program collects metadata from the dentry/inode.
3. Event is sent via ring buffer to user space.
4. User space prints the event.

## 3) Kernel-side details (filewatch.bpf.c)
- Hooks:
  - `kprobe/vfs_open`
  - `kprobe/vfs_write`
  - `kprobe/vfs_unlink`
  - `kprobe/vfs_rename`
- Filters:
  - Only regular files (checks inode mode for `S_IFREG`).
  - Ignores events generated by the tracer process itself using an `ignore_pid` map.
- Event fields:
  - `pid`, `uid`, `op` (open/write/delete/rename)
  - `inode`, `dev` (superblock device ID)
  - `filename` (dentry name only, not full path)

## 4) User-space details (filewatch.c)
- Loads and attaches BPF skeleton; sets `ignore_pid` to its own PID.
- Reads events from a ring buffer and prints:
  - operation name, PID/UID, inode, dev, and filename.
- No extra filtering or severity logic in user space; output is raw activity.

## 5) Build and run (Makefile)
- Builds libbpf locally from `../third_party/libbpf`.
- Requires:
  - clang, gcc
  - `bpftool` in PATH
  - `vmlinux.h` for target arch in `../third_party/vmlinux/<arch>/vmlinux.h`

Typical steps:
- `make`
- `sudo ./filewatch`

## 6) What is new or notable vs existing tools
- Minimal, verifier-friendly file activity monitor that avoids full-path resolution.
- Self-noise suppression by PID avoids recursion from the tracer process itself.
- Uses VFS kprobes for broad coverage across filesystems.

## 7) Known limitations / considerations
- Only captures the dentry name (no full path), so identical filenames in different directories are indistinguishable.
- Rename reports only the old dentry name; new name is not captured.
- No user-space correlation (e.g., process tree, timestamps, or rate limiting).
- Requires kernel BPF + kprobe support and elevated privileges to load.
